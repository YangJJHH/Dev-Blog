## 복사 생성자

아래의 코드를 보자

```cpp
class Sample
{
private:
	int num1;
	int num2;
public:
	Sample(int n1, int n2) : num1(n1), num2(n2)
	{

	}
};

int main(void)
{
	Sample s1(15, 25);
	Sample s2 = s1;

	return 0;
}
```

Sample s2 = s1; 이부분이 객체의 생성 및 초기화를 연상시킨다.

즉, s2라는 객체를 새로 생성해서 객체 s1과 s2의 멤버 대 멤버 복사가 일어난다고 예상해 볼 수있다. 그런데 실제로 그러한 일이 발생한다.

![[13-1.png]]

위의 그림과 같이 s2 객체가 생성된 다음, s1과 s2간의 멤버 대 멤버 복사가 일어난다.

사실 s2=s1이 아래와 같이 묵시적 변환이 되어서 객체가 생성되는 것이다.

```cpp
Sample s2 = s1;
Sample s2(s1);
```

이 문장에 담겨있는 내용을 정리하면 다음과 같다.

- Sample형 객체를 생성해라.
- 객체의 이름은 s2로 한다
- s1을 인자로 받을 수 있는 생성자의 호출을 통해서 객체생성을 완료한다.

이 과정에서 아래 형태의 복사 생성자가 호출되게 된다.

```cpp
	Sample(const Sample& copy) : num1(copy.num1), num2(copy.num2)
	{
		// 복사 샐성자
	}
```

그런데 정의한 Sample 클래스에는 이러한 유형의 생성자가 정의되어 있지 않다. 그러면 어떻게 호출이 가능했던걸까??

## 디폴트 복사 생성자

> 복사 생성자를 정의하지 않으면, 멤버 대 멤버의 복사를 진행하는 디폴트 복사 생성자가 자동으로 삽입된다.

다음 문장이 이야기 하듯 디폴트 생성자와 마찬가지로 복사생성자도 디폴트 생성자가 존재한다.

그래서 실제로 많은 경우에는 따로 복사 생성자를 정의하지 않아도 된다.

하지만 반드신 복사생성자를 정의해야하는 경우도 있다. 이와 관련한 이야기는 아래에서 다시 진행하겠다.

## 변환에 의한 초기화! 키워드 explicit으로 막을 수 있다

앞서 아래문장이

```cpp
Sample s2 = s1;
```

다음의 형태로 묵시적 변환이 일어나서 복사생성자가 호출된다고 설명하였다.

```cpp
Sample s1(15, 25);
```

이는 결국, 복사 생성자가 묵시적으로 호출된것으로 볼 수 있다. 따라서 위와 같은 유형의 변환이 마음에 들지 않는다면, 복사생자의 묵시적 호출을 허용하지 않으면 된다. 그리고 이러한 목적으로 사용되는 키워드가 explicit이다.

위에서 정의한 복사생성자를 다음과 같이 정의하면,

```cpp
explicit Sample(const Sample& copy) : num1(copy.num1), num2(copy.num2)
{
		// empty
}
```

더 이상 묵시적 변환이 발생하지 않아서 대입 연사자를 이용한 객체의 생성 및 초기화는 불가능하다.
