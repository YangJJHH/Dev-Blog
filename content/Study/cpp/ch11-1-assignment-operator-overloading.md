## 객체간 대입연산의 비밀 : 디폴트 대입 연산자

우선 복사 생성자에 대해 보자

- 정의하지 않으면 디폴트 복사 생성자가 삽입된다
- 디폴트 복사생성자는 멤버대 멤버의 얕은 복사를 진행한다.
- 생성자내에서 동적할당을 한다면, 그리고 깊은 복사가 필요하다면 직접 정의해야한다.

그리고 다음은 대입연산자의 특성이다

- 정의하지 않으면 **디폴트 대입연산자**가 삽입된다.
- 디폴트 대입 연산자는 멤버대 멤버의 얕은 복사를 진행한다.
- 연산자내에서 동적할당을 한다면, 그리고 깊은 복사가 필요하다면 직접 정의해야한다.

이둘은 정말 유사하다. 하지만 호출 시점에 차이가 있다.

복사 생성자가 호출되는 대표적이 예이다

```cpp
Point p1(5,7);
Point p2 = p1;
```

여기서 중요한점은 새로 생성하는 객체 p2의 초기화에 기존 생성된 객체 p1이 사용되었다는 점이다. 따라서 복사 생성자가 호출된다

다음은 대입연산자가 호출되는 예이다

```cpp
Point p1(5,7);
Point p2;
p2 = p1;
```

여기서 중요한점은 p2는 이미 생성 및 초기화가 진행된 객체라는 사실이다.

따라서 p2 = p1은 초기화 시점이 아니라 복사생성자가 호출되지 않고 디폴트 대입연산자가 호출된다.

## 디폴트 대입 연산자의 문제점

디폴트 대입연산자의 문제는 디폴트 복사생성자와 유사하다. 아래 코드를 보자

```cpp
class Person
{
private:
	char* name;
	int age;
public:
	Person(const char* myname, int myage) : age(myage)
	{
		int len = strlen(myname) + 1;
		name = new char[len];
		strcpy(name, myname);
	}
    ~Person()
	{
		delete []name;
	}
};

int main(void)
{

	Person p1("AA", 23);
	Person p2("BB", 21);

	p1 = p2;
	return 0;
}
```

다음과 같이 p1에 p2를 대입하여 디폴트 대입연산자가 호출되면, 두가지 문제가 생긴다

첫번째 AA라는 문자열을 가르키던 p1의 name이 p2의 BB를 가르키면서 AA라는 문자열의 주소값을 잃어버린다. 즉 메모리 누수가 생긴다.

두번째 객체 소멸시 동일한 문자열 BB를 가르키는 메모리를 해제하면서, 중복 해제의 문제가 발생한다.

그래서 대입연산자 오버로딩시 두가지의 형태의 방벙을 진행해야 문제가 해결된다

- 깊은 복사를 진행하도록 정의한다
- 메모리 누수가 발생하지 않도록 깊은복사에 앞서 메모리 해제를 진행한다.

그렇다면 이렇게 대입연산자를 오버로딩 할 수 있을것이다

```cpp
	Person& operator=(Person& ref)
	{
		delete[]name; // 메모리 누수를 방지하기 위한 해제

		int len = strlen(ref.name) + 1;
		name = new char[len];
		age = ref.age;
		strcpy(name, ref.name);

		return (*this);
	}
```
