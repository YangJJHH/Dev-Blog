# Unreal Prefix 정리 (F / U / A / E / I / T)

## 🔥 한 줄 핵심

- **F = 일반 데이터 타입 (UObject 아님, GC 없음)**
    

---

## 🧠 언리얼 접두사 규칙

|접두사|의미|
|---|---|
|U|UObject 계열 (엔진 관리 객체)|
|A|Actor (월드에 존재)|
|F|일반 값 타입 (struct / non-UObject class)|
|E|Enum|
|I|Interface|
|T|Template|

---

## 🎯 F 접두사 기준

### ✔️ 값 타입 (Value Type)

- UObject 아님
    
- GC 대상 아님
    
- 스택처럼 사용
    
- 복사 가능
    

```cpp
FVector Location;
FString Name;
FTransform Transform;
```

---

## 💡 대표 F 타입

- FVector → 위치/방향
    
- FString → 문자열
    
- FTransform → 위치 + 회전 + 스케일
    
- FColor → 색상
    

👉 전부 "데이터 덩어리"

---

## ⚙️ UObject vs F 타입 차이

|항목|UObject|F 타입|
|---|---|---|
|메모리 관리|GC|없음|
|생성 방식|NewObject|그냥 선언|
|사용 방식|포인터|값|
|엔진 연동|O|X|

---

## 💡 왜 F를 붙이냐?

### 1. UObject와 구분

```cpp
UObject* Obj;
FVector Vec;
```

---

### 2. 라이프사이클 차이

- UObject → 엔진이 관리
    
- F 타입 → 그냥 C++ 변수
    

---

### 3. 복사 가능

```cpp
FVector A = B; // OK
```

---

## 🚨 헷갈리는 포인트

### ❗ struct는 무조건 F 붙나?

- 대부분 맞음 (언리얼 스타일일 때)
    

```cpp
USTRUCT()
struct FMyData
{
    GENERATED_BODY()
};
```

---

### ❗ class인데 F 붙는 경우?

- 있음 (UObject 아니면)
    

예:

- FStreamableManager
    
- FSlateBrush
    

👉 기준은 "UObject 여부"

---

## 💥 핵심 구분법

```text
U → 엔진 객체 (GC, 리플렉션)
A → 월드 Actor
F → 순수 데이터
```

---

## 🎯 실무 기준

### ✔️ F 타입 사용

- 위치, 회전, 스케일
    
- 문자열
    
- 색상
    
- 계산용 데이터
    

---

### ✔️ UObject 사용

- Actor
    
- Component
    
- Asset
    

---

## 💣 한줄 요약

👉 F = "엔진이 관리하지 않는 순수 데이터 타입"
