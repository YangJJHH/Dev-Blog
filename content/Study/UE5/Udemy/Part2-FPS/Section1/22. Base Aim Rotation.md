90 ~ -90을 사용하는데 GetBaseAimRottion에서는 270~360값이 나올수도 있기 때문이네
270도와 -90도는 사실상 같은 각도

그래서 이걸 AimOffset이 기대하는 각도로 변환해서 전달해줘야 한다

```cpp
FRotator AShooterCharacter::GetFixedAimRotation() const
{
	FRotator AimRotation = GetBaseAimRotation();

	// map pitch from [270, 360) to [-90, 0]
	if( AimRotation.Pitch > 90.0f  && !IsLocallyControlled())
	{
		const FVector2D InRange(270.f, 360.f);
		const FVector2D OutRange(-90.0, 0.0f);

		AimRotation.Pitch = FMath::GetMappedRangeValueClamped(InRange, OutRange, AimRotation.Pitch);
	}

	return AimRotation;
}
```

따라서 다음과 같음 함수로 조정해주는데
문제가 되는 범위 InRange(270.f, 360.f) 를 기대 범위 OutRange(-90.0, 0.0f) 로 선형적으로 범위에 맞는 비율로 매핑해주는 함수가 FMath::GetMappedRangeValueClamped 이다

그럼 왜 >90.0f 조건이지?
90~270까지 범위에 없는 것은 자동으로 최솟값 -90으로 매핑함수가 처리해준다고 한다
