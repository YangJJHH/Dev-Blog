# 이제 설정한 IA와 IMC를 컨트롤러에서 바인딩해보자!

마찬가지로 APlayerController를 상속받아 ShooterPlayerController 클래스를 만들어주자

우선 생성자에서 다음과 같이 설정한다

```cpp
AShooterPlayerController::AShooterPlayerController()
{
	bReplicates = true;
}
```

이게 무슨의미냐?

Replicate는 네트워크 복제.
즉 서버와 클라의 동기화, 다시 말해 서버의 값으로 클라이언트 값을 동기화 시키겠다는 의미이다.

그래서 bReplicates = true; 이거의 의미는 해당 엑터를 네트워크 복제 시키겠다는 뜻.
이건 RPC, Replication, 데디서버를 알아야 하는 개념인데 추후 정리

참고로 캐릭터가 컨트롤러를 컴포넌트처럼 소유하는 개념이 아니라 서로 독립적인 Actor이다
Posses되면 컨트롤러가 캐릭터를 조종한다.

## 그럼 Character는 누가 소유하지?

여기서 "Owner"라는 개념이 나온다.

보통:

```
PlayerController
        |
        | Possess
        ↓
Character
```

하면 Character의 Owner가 PlayerController가 된다.

이후 BeginPlay에서 IMC를 서브시스템에 설정해주는데

```cpp
void AShooterPlayerController::BeginPlay()
{
	Super::BeginPlay();

	UEnhancedInputLocalPlayerSubsystem* Subsystem = ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(GetLocalPlayer());
	if (IsValid(Subsystem))
	{
		Subsystem->AddMappingContext(ShooterIMC, 0); // IMC, Priority
	}
}
```

코드가 난해한데; 풀어서 보자면

먼저 ULocalPlayer 라는것은
`ULocalPlayer`는 **클라이언트 한 명의 로컬 플레이어 정보를 관리하는 객체**이고 Actor가 아니다

구조는 아래와 같다
```
Client PC

ULocalPlayer
      |
      ↓
PlayerController
      |
      ↓
Character
```

즉 GetLocalPlayer()는 컨트롤러의 함수인데 현재 컨틀롤러에 연결된 LocalPlayer 객체를 가져와 그 객체에서 사용하는 UEnhancedInputLocalPlayerSubsystem 포인터를 가져와서 IMC를 설정하는것이다


그럼 이제 SetupInputComponent에서 바인딩을 해주자

```cpp
void AShooterPlayerController::SetupInputComponent()
{
	Super::SetupInputComponent();

	UEnhancedInputComponent* ShooterInputComponent = CastChecked<UEnhancedInputComponent>(InputComponent);
	ShooterInputComponent->BindAction(MoveAction, ETriggerEvent::Triggered, this, &ThisClass::Input_Move);
	ShooterInputComponent->BindAction(LookAction, ETriggerEvent::Triggered, this, &ThisClass::Input_Look);
	ShooterInputComponent->BindAction(CrouchAction, ETriggerEvent::Started, this, &ThisClass::Input_Crouch);
	ShooterInputComponent->BindAction(JumpAction, ETriggerEvent::Started, this, &ThisClass::Input_Jump);
}

```

참고로 CastChecked 는 Cast와 다르게 캐스팅 실패하면 nullptr 뱉는게 아니라 바로 크래시, Asserttion

ETriggerEvent 이 Enum만 생소한데
Triggered : 입력이 유지되는 동안 게속 콜백이 호출되는거고
Started : pressed 개념 눌린 시점에 호출
Completed : released 개념 키 입력을 마쳤을떄
Ongoing :  차징 같이, 0.5초후 발동이라면 아직 조건에 못미치고 진행중인 상태

void AShooterPlayerController::Input_Jump()
{
	if (!IsValid(GetCharacter())) return;

	UCharacterMovementComponent* CMC = GetCharacter()->GetCharacterMovement();

	if (!IsValid(CMC)) return;

	if (CMC->bWantsToCrouch)
	{

	}
}

## Move

```cpp
void AShooterPlayerController::Input_Move(const struct FInputActionValue& InputActionValue)
{
	const FVector2D InputAxisVector = InputActionValue.Get<FVector2D>();
	const FRotator Rotation = GetControlRotation();
	const FRotator YawRot(0.0f, Rotation.Yaw, 0.0f);

	const FVector ForwardDirection = FRotationMatrix(YawRot).GetUnitAxis(EAxis::X);
	const FVector RightDirection = FRotationMatrix(YawRot).GetUnitAxis(EAxis::Y);

	APawn* ControlledPawn = GetPawn();
	ControlledPawn->AddMovementInput(ForwardDirection, InputAxisVector.Y);
	ControlledPawn->AddMovementInput(RightDirection, InputAxisVector.X);
}
```

`FRotationMatrix`는:
> **FRotator(오일러 각도)를 기반으로 만든 회전 행렬(Matrix)**

그럼 왜 굳이 행렬로 바꾸냐?
FRotator는 방향 벡터가 아니라 오일러 각도임 (x축으로 몇도, y축으로 몇도, z축으로 몇도)
근데 우리가 구할껀 내가 바라보는 방향으로의 상하좌우 방향으로의 움직임이니깐 방향벡터가 필요함.

그래서 FRotationMatrix 는 FRotator 만큼 회전을 적용했을때 물체의 각 로컬 축(X,Y,Z)가 월드상 어떤 방향을 향하는지를 나타낸다.

그래서 우리가 원하는 앞을 바라보는 방향 GetUnitAxis(EAxis::X)
오른쪽을 나타내는 GetUnitAxis(EAxis::Y) 을 구해서 그쪽 방향으로 AddMovementInput을 통해 입력값만큼 움직여주면된다.

저렇게 두 방향만 전달해도 내부적으로 두 벡터를 합산해서 계산하기 때문에 상하좌우,대각선 모두 대응 가능

## Look
```cpp
void AShooterPlayerController::Input_Look(const struct FInputActionValue& InputActionValue)
{
	const FVector2D InputAxisVector = InputActionValue.Get<FVector2D>();
	AddYawInput(InputAxisVector.X);
	AddPitchInput(InputAxisVector.Y);
}
```
마우스 좌우(X)입력값을 Yaw로 즉 왼쪽 오른쪽 회전
마우스 상하(Y)입력값을 Pitchfh 즉 위 아래 회전

AddYawInput, AddPitchInput는 컨트롤러의 회전만을 바꾸는 것이다.
근데 우리는 캐릭터 클래스에서 SpringArm->bUsePawnControlRotation = true; 이렇게 해준 적이 있다. 근데 팔 메쉬는 springArm 따라돌아갈텐데 전신메쉬는?? 

일단 기본적으로 Character는
```cpp
bUseControllerRotationPitch = false;
bUseControllerRotationYaw = true;
```
이렇게 yaw회전 활성화 되어있음 그래서 좌우로는 컨트롤러 값에 따라 회전 하지만 pitch로는 회전을 안함. 그래서 전신메쉬는 좌우로 돌아가는거고
스피링암은 상하 pitch값도 회전해야하기 때문에 또 따로 bUsePawnControlRotation 이걸 키는거다. 둘다 true라고 중복되어서 회전되는건 아니고 컨트롤러에  relative한 회전을 함.


이동관련 Replicates에 대해
위와 같은 기본동작들은 이미 언리얼에서 구현해놓은 동작들이고 

```
Client 입력
 ↓
CharacterMovementComponent
 ↓
Movement 네트워크 시스템
 ↓
Server 처리
 ↓
Replication
```
이런 애들은 위와 같은 구조로 CharacterMovementComponent를 통해 서버에서 클라 예측 값을 같이 시뮬레이션해서 계산하고 계산값이 맞으면 클라이언트들한테 브로드캐스팅 한다
