## 이제 WeaponData를 컴뱃 컴포넌트에 넣어 관리해보도록하자

CombatComponent에 DataAsset 받을 수 있도록 해주고
```cpp
	UPROPERTY(EditDefaultsOnly, Category = "FPS|Weapon")
	TObjectPtr<class UWeaponData> WeaponData;
```

UInterface를 상속받는 IPlayerInterface를 만들어주자
```cpp
UINTERFACE(MinimalAPI)
class UPlayerInterface : public UInterface
{
	GENERATED_BODY()
};

/**
 * 
 */
class FPS_API IPlayerInterface
{
	GENERATED_BODY()

	// Add interface functions to this class. This is the class that will be inherited to implement this interface.
public:
	UFUNCTION(BlueprintNativeEvent, BlueprintCallable)
	FName GetWeaponAttachPoint(const FGameplayTag& WeaponTag) const;
};
```
언리얼 인터페이스는 C++ 네이티브 인터페이스와 조금 다름
클래스가 2개 생성되고 아래 클래스에 추가할 기능을 선언해주면됨.

근데 virtual이 없는데 BlueprintNativeEvent는 안붙여도된다고함


BlueprintImplementableEvent = 구현을 Blueprint에서만 한다.
BlueprintNativeEvent = C++에서 기본 구현을 제공할 수도 있고, Blueprint에서 덮어쓸 수도 있다.

이제 ShooterCharacter 클래스에 인터페이스를 추가해주고

```cpp
class FPS_API AShooterCharacter : public ACharacter, public IPlayerInterface
{
		/* PlayerInterface*/
	virtual FName GetWeaponAttachPoint_Implementation(const FGameplayTag& WeaponTag) const override;
	/* ~PlayerInterface*/
}
```

단 BlueprintNativeEvent 는 c++에서 기본 구현을 제공할떄 기존 함수이름이 아니라 _Implementation을 붙여야 한다.

그리고 나서 이 인터페이스를 ShooterCharacter 붙여서 기능을 구현하자
```cpp
FName AShooterCharacter::GetWeaponAttachPoint_Implementation(const FGameplayTag& WeaponTag) const
{
	checkf(CombatComp->WeaponData, TEXT("No Weapon Data Asset"));
	return CombatComp->WeaponData->GripPointsMap.FindChecked(WeaponTag);
}
```

이렇게 되면 나중에 캐릭터에서 무기를 획득 했을 떄 바로 어떤 소켓에 장착할지 알 수 있다
또한 새로운 무기가 생기거나 새로운 그립포인트가 생길때마다 코드에 추가하는게 아니라
데이터 에셋에 데이터만 추가하면 된다.

근데 지금은 ShooterCharacter에서만 쓰니깐 굳이 왜 인터페이스로 돌아가나 싶음..
