#Transient #GetLifetimeReplicatedProps #AddUnique
# 이제 Default Weapon 단일 대신 인벤토리 개념을 추가하여 TArray 배열로 관리해보자


```cpp
UPROPERTY(EditDefaultsOnly, Category = "FPS|Weapon")
TArray<TSubclassOf<AWeapon>> DefaultWeaponClasses;
```
배열로 바꾸어주자.
이건 실제 인스턴스된 무기들이 아니라 어떤 무기들을 생성할지에 대한 클래스 타입 배열임.

따라서 실제 생성된 무기를 관리할 배열도 있어야겠지?
```cpp
UPROPERTY(Transient, Replicated)
TArray<TObjectPtr<AWeapon>> Inventory;
```
이게 실제 무기들을 관리할 인벤토리 배열이고.
이 정보는 Replicate 되어야 하기 때문에 설정

# Transient 이거는 뭐냐?
이거는 해당 값을 객체를 Serialization 할떄 제외하라는 의미
언리얼에서는 객체의 정보를 파일에 저장하거나 반대로 파일에서 메모리로 가져올떄 직렬화를 쓰게되는데, 이렇게 런타임에 결정되는 데이터는 그렇게 저장되면 안되기 때문에 붙여준다함.


# GetLifetimeReplicatedProps
그 다음 실제로 해당 함수를 오버라이딩 해야 Replicated가 되는데
실제 해당 객체에서 복제할 변수들을 리스트에 등록해주는 곳이라 생각하면된다.

```cpp
void UCombatComponent::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
	Super::GetLifetimeReplicatedProps(OutLifetimeProps);

	DOREPLIFETIME(UCombatComponent, Inventory);
}
```

내가 직접 UPROPERTY(Replicated) 해준 애들은 세트로 저기 함수까지 등록해야한다.

그 이후 SpawnInvetory 함수를 다음과 같이 바꿔준다
```cpp
void UCombatComponent::SpawnInventory()
{
	if (GetOwner()->GetLocalRole() < ROLE_Authority) return;
	for( TSubclassOf<AWeapon>& WeaponClass : DefaultWeaponClasses)
	{
		if(!IsValid(WeaponClass)) continue;
		AWeapon* NewWeapon = SpawnWeapon(WeaponClass);
		if (!IsValid(NewWeapon)) continue;

		Inventory.AddUnique(NewWeapon);
	}

	if (Inventory.Num() > 0) // Default Attach
	{
		Inventory[0]->AttachToOwningPawn();
	}
}
```

여기도 ROLE_Authority를 체크해서 서버만 생성할 수 있게 해주고
이제 우리 DefaultWeaponClasses에 있는 무기들을 모두 생성해준 후
AddUnique를 통해 중복 없이 추가해준다

그 이후 첫번째 무기를 어태치시켜준다.
