우선 조준했다는 변수를 만들고

```cpp
	UPROPERTY(BlueprintReadOnly, Replicated)
	bool bAiming;
```

마찬가지로 복제가능하게 하되, 이번에는 특이하게 조건을 건다

```cpp
	DOREPLIFETIME_CONDITION(UCombatComponent, bAiming, COND_SkipOwner);
```

COND_SkipOwner 이거는 오너 클라이언테는 복제를 하지 않게다는 의미인데.
bAiming이라는 변수자체가 오너 클라이언트가 제어하는 값이기 때문에  굳이 다시 복제하지 않음

이제 저 변수를 클라이언트에 에임키를 눌러 변경한다고 했을떄 그것을 서버한테도 알려야 다른 클라이언트한테 복제가 되겠지??

그래서 RPC가 등장한다

#RPC
# RPC

우선 RPC라는 개념은 서버-클라 사이의 함수호출을 통한 통로? 라고 생각하면된다
뭔가 Send Recv 개념이라 생각하면 이해하기 쉬울거같음

## 1. Client → Server
```cpp
UFUNCTION(Server, Reliable)
void ServerEquipWeapon();
```

## 2. Server → Client

```cpp
UFUNCTION(Client, Reliable)
void ClientShowSomething();
```

## 3. Server → 여러 Client
```cpp
UFUNCTION(NetMulticast, Reliable)
void MulticastPlayFireEffect();
```

각각 함수 이름_Implemetation() 의 함수가 상대편에서 호출되어 처리하게된다
즉 Reliable로 선언한 함수가 send라 하면 \_Implemetation() Recv라고 보면된다

즉 ServerEquipWeapon 이런 함수는 클라에서 뭔가 내부를 구현하는게 아니라 호출 용도이고. 저게 호출되었을때 실제 상대편에서 처리할  \_Implemetation() 해당 함수를 구현해야한다

그래서 우리는

```cpp
	UFUNCTION(Server, Reliable)
	void Server_Aim(bool bPressed);
```
해당 함수를 선언하고


아래처럼 Implemtation에 실제 서버에서 처리할 내용을 구현해준다.
```cpp
void UCombatComponent::Server_Aim_Implementation(bool bPressed)
{
	bAiming = bPressed;
}
```

그럼 실제로 클라이언트에서 에임을 누르고 뗴는 부분에서는
```cpp
void UCombatComponent::Initiate_AimPressed()
{
	GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Green, TEXT("Aim Pressed"));

	Local_Aim(true);
	Server_Aim(true);
}

void UCombatComponent::Initiate_AimReleased()
{
	GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Green, TEXT("Aim Released"));

	Local_Aim(false);
	Server_Aim(false);
}
```

이렇게 RPC를 호출하기만 하면된다 Local_Aim 은 단순히 bAiming = bPressed 하는 함수

이제 bAming을 서버-클라 에서 모두 잘 제어하니 이 변수를 통해 AnimationBlueprint를 통해 애니메이션에 적용해보자
