
# FPS에 맞게 우리는 Character에 2개의 메쉬를 갖을것이다.

1. 내가 보는 캐릭터의 팔
2. 다른 플레이어가 보는 전신 캐릭터

그래서 다음과 같이 컴포넌트들을 AShooterCharacter에 선언해주고
```cpp
	UPROPERTY(VisibleAnyWhere)
	TObjectPtr<USkeletalMeshComponent> Mesh1p;

	UPROPERTY(VisibleAnyWhere)
	TObjectPtr<class USpringArmComponent> SpringArm;

	UPROPERTY(VisibleAnyWhere)
	TObjectPtr<class UCameraComponent> FirstPersonCamera;
```


# 기본적인 컴포넌트 구성
```cpp
// 생성자에서
	SpringArm = CreateDefaultSubobject<USpringArmComponent>(TEXT("SpringArm"));
	SpringArm->SetupAttachment(GetRootComponent());
	SpringArm->TargetArmLength = 0.f;
	SpringArm->bEnableCameraLag = true;
	SpringArm->CameraLagSpeed = 15.f;
	SpringArm->bUsePawnControlRotation = true;

	FirstPersonCamera = CreateDefaultSubobject<UCameraComponent>(TEXT("FirstPersonCamera"));
	FirstPersonCamera->SetupAttachment(SpringArm);
	FirstPersonCamera->bUsePawnControlRotation = false;
	
```
컴포넌트들을 생성해준다.
1인칭이기 때문에 TargetArmLength는 0으로 세팅하고, 
카메라가 약간 늦게 따라오도록 bEnableCameraLag,CameraLagSpeed을 설정해준다
bUsePawnControlRotation는 마우스 회전으로 Controller의 회전이 변화되면 카메라도 회전하게끔
카메라의 UsePawnControlRotation는 꺼서 SpringArm의 회전에 따르도록

근데 둘다키면 어떻게 되려나


# 1인칭용 메쉬 설정
```cpp
	Mesh1p = CreateDefaultSubobject<USkeletalMeshComponent>("Mesh1P");
	Mesh1p->SetupAttachment(FirstPersonCamera);
	Mesh1p->bOnlyOwnerSee = true;
	Mesh1p->bOwnerNoSee = false;
```
그리고 손에 해당하는 메쉬는 카메라의 붙여준다.
bOnlyOwnerSee 이게 중요한데, 자신을 소유한 엑터만 보이게끔 하는 옵션
즉 1인칭에서 자기 자신만 팔 메쉬가 보이고 다른 유저들한테는 안보이게 하는 옵션

bOwnerNoSee는 기본적으로는 false인데 명시적으로 적어주는듯

# 최적화 설정
```cpp
	Mesh1p->bCastDynamicShadow = false;
	Mesh1p->bReceivesDecals = false;
	Mesh1p->VisibilityBasedAnimTickOption = EVisibilityBasedAnimTickOption::OnlyTickPoseWhenRendered;
```
또한 최적화와 자연스러움을 위해 동적 그림자를 꺼주고, 
Decals 은 총알자국 같은거가 생기는 옵션인데 마찬가지로 꺼준다

VisibilityBasedAnimTickOption 해당 옵션도 최적화로 언제 애니메이션을 업데이트를 할지 정하는 옵션인데. OnlyTickPoseWhenRendered 이걸로 랜더링될때 즉 자기자신에게만 보일때 애니메이션을 업데이트 해주도록 한다.

설정값이 엄청 많은데.. 또 있다
```cpp
Mesh1p->PrimaryComponentTick.TickGroup = TG_PrePhysics;
```

PrimaryComponentTick.TickGroup 이거는 어떤 TickGroup에 속해 업데이트 순서를 정해주는건데 
언리얼에는 아래와 같은 순서로 프레임 처리가 일어나고
```
한 프레임 시작
    ↓
TG_PrePhysics
    ↓
물리 시뮬레이션
    ↓
TG_DuringPhysics
    ↓
TG_PostPhysics
    ↓
렌더링
```

TG_PrePhysics 를 통해 물리 계산보다 먼저 처리되게끔 하는것이다.

이렇게 하는 이유는 내가 이해하기엔 1인칭에서 팔의 움직임이 곧 총의 움직임이 될텐데,
총알을 발사해서 그 총알의 물리 처리를 하기전 총의 위치를 먼저 업데이트해서 한틱 늦게 발사되는것처럼 보이게 하는것을 보정하려고 하는거 같다.

강의에서는 좀더 원활한 경험을 위해 한다고 하는데 해석이 정확한지 모르겠음;

# Skeleton, SkeletalMesh, PhysicsAsset
![[Pasted image 20260805001350.png]]

한마디로 Skeleton 은 애니메이션이나 Skeletal Mesh 를 위한 기본 구조이고,
Skeletal Mesh는 랜더용, Physics Asset 은 물리 충돌을 처리하기 위한 용도.

Skeletal Mesh로 직접 충돌 처리하기엔 메쉬가 너무 복잡해서 부하가 생길 수 있기 때문.
