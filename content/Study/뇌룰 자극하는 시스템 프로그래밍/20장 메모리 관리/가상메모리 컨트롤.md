가상 메모리는 각 3개의 상태가 있다
Commit 
- 물리 메모리에 할당된 메모리
Reserve 
-  물리 메모리에 예약된 메모리
free 
- 할당되지 않은 메모리
(여기셔 물리 메모리는 메인메모리와 하드디스크 모두를 의미한다.)

가상메모리 크기 / 페이지 하나의 크기 = 페이지 갯수

여기서 Reserve란 개념이 등장하게 된 이유는 아주 큰 배열을 메모리할당할때의 문제이다
배열같은 경우 연속적인 메모리에 할당해줘야 한다. 미리 큰 배열을 선언하기에는 효율성에 문제가 되고 점차 조금씩 메모리를 필요에 맞게 할당하자니 연속된 메모리 공간에 할당해주지 못하는 문제가 생긴다. 이로인해 Reserve란 개념이 등장한다.
Reserve는 Commit과 free의 중간상태이다. 메모리를 Reserve로 선언해두면 다른 곳에서 메모리를 할당 받을때 해당 번지를 찾지 못하게 하는 특성이 있다.


**메모리 할당의 시작주소, 할당할 메모리 크기**
가상 메모리 시스템은 페이지 단위로 관리되기 때문에 페이지의 중간 위치에서부터 할당을 시작할 수 없으며, 페이지 크기의 배수 단위로 할당을 해야만 한다.
따라서 현재 시스템에서 사용하는 페이지의 알아야만 합리적인 메모리 할당을 요구 할 수 있다.
코드에서는 GetSystemInfo()함수를 통해서 알 수 있다.
